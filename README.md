# Dialog Auth

Server-side registration and login for Fabric Minecraft 1.21.6, with an optional client companion for encrypted offline authentication and signed modpack synchronization.

Version 1.5.0 adds hybrid Microsoft/offline authentication, one-time-code password resets and a small HTTPS download/reset website. The companion is still built by Gradle and embedded into the server JAR, which generates the client kit on startup.

## Features

- Vanilla registration/login dialogs during the configuration phase; players do not enter the world before authentication.
- Optional hybrid mode: verified Microsoft profiles use vanilla encrypted login and skip the server password, while offline profiles use the companion flow.
- UUID-based accounts, PBKDF2-HMAC-SHA256 with 210,000 iterations and per-account salts.
- Atomic `accounts.json` writes with owner-only permissions.
- One-time password-reset codes stored as PBKDF2 hashes, 15-minute expiry, five failed attempts, and an operator `/dialogauth resetcode <username>` command.
- Localhost-only reset API with a bearer token; the included Python website serves downloads and a reset form without JavaScript.
- Shared per-player/IP rate limits, bounded background workers, timeouts and replay-safe session state.
- Offline mode support with canonical usernames and password-gated login for existing online UUID accounts.
- Companion-only encrypted password responses in offline mode: signed ephemeral X25519 handshake, Ed25519 server identity, HKDF-SHA256, AES-GCM and response sequence numbers.
- Signed modpack manifest and SHA-256 verification for every downloaded JAR, staging, backups and restart-on-change.
- Versioned-filename cleanup on sync: the companion moves superseded versions of managed mod ids into `.dialogauth-backup`, preventing duplicate mods.
- Server-generated initial client kit: at startup the server atomically writes a stable `dialog-auth-client.zip` containing the main mod, the companion and Fabric API, plus a Russian `INSTALL.txt` for Prism.
- Missing-companion and plaintext-response messaging with a configurable download link.

## Requirements

- Minecraft Java Edition 1.21.6
- Fabric Loader 0.17.3 or newer
- Fabric API 0.128.2+1.21.6 or newer
- Java 21

## Artifacts

- `dialog-auth-1.5.0.jar` — server mod and shared protocol code. Self-contained for the server: it embeds the compiled companion as a resource, so the server extracts it into the client kit at startup and never compiles it at runtime.
- `dialog-auth-companion-1.5.0.jar` — client-only encrypted authentication and modpack synchronization. Built by Gradle from the `src/companion` source set and embedded into the server JAR. The standalone companion artifact (for example, the GitHub Actions upload) is now only a backup/fallback for manual installation; the primary distribution path is the server-generated client kit.
- `dialog-auth-client.zip` — generated by the server at startup as `client-kit-path/dialog-auth-client.zip` (default directory `client-kit`; see Configuration). It contains:
  - `mods/dialog-auth-1.5.0.jar` — a copy of the server's own production JAR,
  - `mods/dialog-auth-companion-1.5.0.jar` — the companion extracted from the embedded resource,
  - `mods/fabric-api-0.128.2+1.21.6.jar` — the Fabric API installed on the server,
  - `INSTALL.txt` — Russian installation instructions for Prism,
  - `config/dialogauth/modpack.properties` — only when both `client-modpack-manifest-url` and `client-modpack-servers` are set; a public client config that enables automatic subsequent synchronization.
  The ZIP contains no private keys, `accounts.json`, server config, secrets or worlds.

## Build

```bash
./gradlew clean build
```

Gradle compiles both source sets and packages:

- `build/libs/dialog-auth-1.5.0.jar` — server mod with the companion resource embedded.
- `build/libs/dialog-auth-companion-1.5.0.jar` — standalone companion (backup artifact).

The companion is compiled at build time and stored in the server JAR as a ready-to-extract resource. The server does not compile the companion at runtime; at startup it only extracts that resource and copies the JARs into the client kit.

To also produce a signed manifest for subsequent (update) synchronization:

```bash
./gradlew clean build generateModpack
```

Generated files:

- `build/modpack/` — copied artifacts and `manifest.json`.

Generate a signing key pair:

```bash
java -cp build/classes/java/companion ru.ldpe.dialogauth.client.ModpackSigner generate private.key public.key
```

Sign the generated manifest:

```bash
./gradlew signModpack -PmodpackSigningKey=/absolute/path/private.key
```

Keep private keys outside the repository. The modpack HTTP directory should contain only `manifest.json`, `manifest.sig`, `modpack-public.key`, `mods/` and, for the initial kit, `client/`.

## Initial client installation (Prism)

1. At startup the server atomically writes `dialog-auth-client.zip` into the `client-kit-path` directory (always `client-kit-path/dialog-auth-client.zip`) and serves it at `client-download-url`.
2. The player downloads the ZIP and unpacks it into the root of the Prism instance — the directory that already contains `mods/`. The `mods/` folder inside the ZIP merges into the instance's `mods/`, `INSTALL.txt` lands in the instance root with the Russian steps, and, when present, `config/dialogauth/modpack.properties` merges into the instance's `config/`.
3. The player restarts the instance before connecting. The restart is mandatory: Fabric loads the new mods only after a full restart.

The initial kit bootstraps a fresh instance. After that, updates flow through the existing signed-modpack path (`manifest.json`), which stages, backs up and SHA-256-checks every downloaded JAR.

### Upgrading from 1.3.0

The 1.3.0 companion does not clean up old versioned JARs. Before installing the 1.5.0 client kit and restarting, manually delete `dialog-auth-1.3.0.jar` and `dialog-auth-companion-1.3.0.jar` from the instance's `mods/` once. Otherwise both 1.3.0 and 1.5.0 JARs remain loaded and Fabric reports duplicate mods. From 1.4.0 onward, sync moves superseded versions of managed mod ids into `.dialogauth-backup` automatically.

## Configuration

Server `config/dialogauth/config.properties`:

```properties
allow-offline-mode=true
require-encrypted-auth=true
client-kit-path=/opt/modpack/client
client-download-url=https://gang.ldp-e.ru/
client-modpack-manifest-url=https://gang.ldp-e.ru/downloads/manifest.json
client-modpack-servers=gang.ldp-e.ru:25565
# Hybrid mode requires online-mode=true in server.properties.
microsoft-auth=true
microsoft-profile-url=https://api.mojang.com/users/profiles/minecraft/
# Optional website-driven password reset; use a unique random token.
reset-api-enabled=true
reset-api-port=25578
reset-api-token=replace-with-a-long-random-token
reset-code-ttl-minutes=15
```

- `client-kit-path` — directory for the atomically written client kit; the ZIP is always `client-kit-path/dialog-auth-client.zip`. Defaults to `client-kit`.
- `client-download-url` — stable URL where the kit is published. Defaults to empty.
- `client-modpack-manifest-url` and `client-modpack-servers` — public sync settings baked into the client kit.
- `microsoft-auth` — when enabled together with `online-mode=true`, a Mojang profile/UUID match enters vanilla Microsoft encryption and skips Dialog Auth. Other profiles receive an offline UUID and use the companion flow. Lookup failures fail closed with a retry message.
- `reset-api-enabled` — starts the reset API only on `127.0.0.1`. A token of at least 32 characters is required. Never expose this port publicly.

For an offline-only server, set `online-mode=false`, `microsoft-auth=false`, and `allow-offline-mode=true`. Keep `require-encrypted-auth=true` unless plaintext password responses are explicitly accepted. In hybrid mode, keep `online-mode=true`; offline profiles still require the companion.

Client `config/dialogauth/modpack.properties`:

```properties
url=https://gang.ldp-e.ru/downloads/manifest.json
servers=gang.ldp-e.ru:25565
```

The initial kit can generate this public client config automatically. The first server identity and modpack signing key are pinned on first use; share fingerprints through a separate trusted channel.

## Download and reset website

The `website/` directory contains a dependency-free Python backend, accessible HTML forms, tests and deployment examples. The production site is `https://gang.ldp-e.ru/`; the reset form is `https://gang.ldp-e.ru/reset`. Caddy proxies downloads to the modpack HTTP service and the reset form to the local backend. The backend shares the mod's bearer token through a root-readable-only configuration and applies a five-attempt/15-minute IP limit.

An operator issues a reset code in game or from the console:

```text
/dialogauth resetcode PlayerName
```

The player enters that six-digit code and a new password on the reset page. Codes are PBKDF2-hashed at rest, expire after 15 minutes, allow five failures, and are deleted after a successful reset. Run website tests with `cd website && python3 -m unittest -v test_server.py`.

## Security notes

Offline profiles do not receive Microsoft verification. Any unregistered offline name can be claimed by its first registrant. Use unique passwords and do not reuse credentials from other services. Modpack installation executes Java code on the next restart, so publish only signed manifests and review updates.

Serve the initial kit and manifest over HTTPS. Subsequent sync also verifies the manifest signature and every JAR's SHA-256. Never commit reset tokens, reset-code files, account stores, signing keys or server identity keys.
