# Dialog Auth

Server-side registration and login for Fabric Minecraft 1.21.6, with an optional client companion for encrypted offline authentication and signed modpack synchronization.

Version 1.4.0 changes initial installation: the companion is built by Gradle and embedded into the server JAR, and the server generates a stable client kit (`dialog-auth-client.zip`) on startup instead of requiring players to assemble the mods by hand.

## Features

- Vanilla registration/login dialogs during the configuration phase; players do not enter the world before authentication.
- UUID-based accounts, PBKDF2-HMAC-SHA256 with 210,000 iterations and per-account salts.
- Atomic `accounts.json` writes with owner-only permissions.
- Shared per-player/IP rate limits, bounded background workers, timeouts and replay-safe session state.
- Offline mode support with canonical usernames and password-gated login for existing online UUID accounts.
- Companion-only encrypted password responses in offline mode: signed ephemeral X25519 handshake, Ed25519 server identity, HKDF-SHA256, AES-GCM and response sequence numbers.
- Signed modpack manifest and SHA-256 verification for every downloaded JAR, staging, backups and restart-on-change.
- Versioned-filename cleanup on sync: the 1.4.0 companion moves superseded versions of the managed mod ids (`dialogauth`, `dialogauth-companion`) into `.dialogauth-backup`, so leftover versioned JARs do not cause duplicate mods.
- Server-generated initial client kit: at startup the server atomically writes a stable `dialog-auth-client.zip` containing the main mod, the companion and Fabric API, plus a Russian `INSTALL.txt` for Prism.
- Missing-companion and plaintext-response messaging: in offline mode, clients without the companion (or sending a plaintext password response) are told about the required client kit, with a download link when one is configured.

## Requirements

- Minecraft Java Edition 1.21.6
- Fabric Loader 0.16.14 or newer
- Fabric API 0.128.2+1.21.6 or newer
- Java 21

## Artifacts

- `dialog-auth-1.4.0.jar` — server mod and shared protocol code. Self-contained for the server: it embeds the compiled companion as a resource, so the server extracts it into the client kit at startup and never compiles it at runtime.
- `dialog-auth-companion-1.4.0.jar` — client-only encrypted authentication and modpack synchronization. Built by Gradle from the `src/companion` source set and embedded into the server JAR. The standalone companion artifact (for example, the GitHub Actions upload) is now only a backup/fallback for manual installation; the primary distribution path is the server-generated client kit.
- `dialog-auth-client.zip` — generated by the server at startup as `client-kit-path/dialog-auth-client.zip` (default directory `client-kit`; see Configuration). It contains:
  - `mods/dialog-auth-1.4.0.jar` — a copy of the server's own production JAR,
  - `mods/dialog-auth-companion-1.4.0.jar` — the companion extracted from the embedded resource,
  - `mods/fabric-api-0.128.2+1.21.6.jar` — the Fabric API installed on the server,
  - `INSTALL.txt` — Russian installation instructions for Prism,
  - `config/dialogauth/modpack.properties` — only when both `client-modpack-manifest-url` and `client-modpack-servers` are set; a public client config that enables automatic subsequent synchronization.
  The ZIP contains no private keys, `accounts.json`, server config, secrets or worlds.

## Build

```bash
./gradlew clean build
```

Gradle compiles both source sets and packages:

- `build/libs/dialog-auth-1.4.0.jar` — server mod with the companion resource embedded.
- `build/libs/dialog-auth-companion-1.4.0.jar` — standalone companion (backup artifact).

The companion is compiled at build time and stored in the server JAR as a ready-to-extract resource. The server does not compile the companion at runtime; at startup it only extracts that resource and copies the JARs into the client kit.

To also produce a signed manifest for subsequent (update) synchronization:

```bash
./gradlew clean build generateModpack
```

Generated files:

- `build/modpack/` — copied artifacts and `manifest.json`.

Generate a signing key pair:

```bash
java -cp build/classes/java/companion ru.ldpe.dialogauth.client.ModpackSigner generate private.key public.key
```

Sign the generated manifest:

```bash
./gradlew signModpack -PmodpackSigningKey=/absolute/path/private.key
```

Keep private keys outside the repository. The modpack HTTP directory should contain only `manifest.json`, `manifest.sig`, `modpack-public.key`, `mods/` and, for the initial kit, `client/`.

## Initial client installation (Prism)

1. At startup the server atomically writes `dialog-auth-client.zip` into the `client-kit-path` directory (always `client-kit-path/dialog-auth-client.zip`) and serves it at `client-download-url`.
2. The player downloads the ZIP and unpacks it into the root of the Prism instance — the directory that already contains `mods/`. The `mods/` folder inside the ZIP merges into the instance's `mods/`, `INSTALL.txt` lands in the instance root with the Russian steps, and, when present, `config/dialogauth/modpack.properties` merges into the instance's `config/`.
3. The player restarts the instance before connecting. The restart is mandatory: Fabric loads the new mods only after a full restart.

The initial kit bootstraps a fresh instance. After that, updates flow through the existing signed-modpack path (`manifest.json`), which stages, backs up and SHA-256-checks every downloaded JAR.

### Upgrading from 1.3.0

The 1.3.0 companion does not clean up old versioned JARs. Before installing the 1.4.0 client kit and restarting, manually delete `dialog-auth-1.3.0.jar` and `dialog-auth-companion-1.3.0.jar` from the instance's `mods/` once. Otherwise both 1.3.0 and 1.4.0 JARs remain loaded and Fabric reports duplicate mods. This manual step is required only for the 1.3.0 → 1.4.0 transition; from 1.4.0 onward, sync moves superseded versions of the managed mod ids into `.dialogauth-backup` automatically.

## Configuration

Server `config/dialogauth/config.properties`:

```properties
allow-offline-mode=true
require-encrypted-auth=true
# Directory where the server writes the generated client kit.
client-kit-path=/opt/modpack/client
# Public URL shown to players when the companion is missing.
client-download-url=http://217.144.184.4:25577/client/dialog-auth-client.zip
# Manifest and server list baked into the client kit for automatic updates.
client-modpack-manifest-url=http://217.144.184.4:25577/manifest.json
client-modpack-servers=217.144.184.4:25565
```

- `client-kit-path` — directory for the atomically written client kit; the ZIP is always `client-kit-path/dialog-auth-client.zip`. Defaults to `client-kit`.
- `client-download-url` — stable URL where the kit is published. Defaults to empty; when set, it is shown in the missing-companion and plaintext-response messages.
- `client-modpack-manifest-url` — manifest URL written into the client kit's `config/dialogauth/modpack.properties`. Defaults to empty.
- `client-modpack-servers` — comma-separated server addresses written into the same client config. Defaults to empty.

When both `client-modpack-manifest-url` and `client-modpack-servers` are set, the ZIP includes the public client `config/dialogauth/modpack.properties` so the installed instance synchronizes subsequent updates automatically. Otherwise the kit contains no client config and the player configures it manually.

For offline clients, set `online-mode=false` in `server.properties`. Keep `require-encrypted-auth=true` unless you explicitly accept plaintext password responses. When a client connects in offline mode without the companion, or sends a plaintext password response while encrypted auth is required, the server rejects the response and, if `client-download-url` is set, shows a message with that download link.

With `online-mode=true`, the vanilla encrypted login path is used and the companion is optional; online-mode behaviour is unchanged and no client kit is required.

Client `config/dialogauth/modpack.properties`:

```properties
url=http://217.144.184.4:25577/manifest.json
servers=217.144.184.4:25565
```

This file drives subsequent signed updates, not the initial kit. When `client-modpack-manifest-url` and `client-modpack-servers` are set, the server pre-fills exactly this file into the kit, so players do not create it by hand. The first server identity and modpack signing key are pinned on first use. Share the server fingerprint with players through a separate trusted channel so they can verify it.

## Security notes

Offline mode does not verify Microsoft usernames. Any unregistered name can be claimed by the first player who registers it. Use unique passwords and do not reuse credentials from other services. Modpack installation executes Java code on the next restart, so publish only signed manifests and review mod updates.

The initial `dialog-auth-client.zip` is not signed and, when served over plain HTTP as in the example above, has no transport protection — prefer HTTPS for `client-download-url` in production. Later updates remain protected regardless: the pinned signing key verifies `manifest.json`/`manifest.sig`, and every downloaded JAR is checked against its SHA-256 before installation.
